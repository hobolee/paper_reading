今天这组论文最清晰的主线，是“LLM 能说会规划”正在被系统性地重写为“系统能否在具体环境里被安全、稳定、低成本地委托做事”。如果只看阅读优先级，我会把 arXiv:2609.04894v1 放在第一位：它不是又一篇泛泛而谈的 agent 综述，而是把 agentic AI 拆成模型本体、外部 harness/编排、持久状态、环境耦合四层，并用“委托权限—时间持续性—环境耦合”三轴来审视数字工具、社会交互、虚拟世界、机器人和自驱实验室中的证据强弱。这个框架对理解今天其余论文非常有用，因为多篇工作其实都在证明：性能增益常常来自接口、上下文、工作流设计和评测方式，而不必然来自模型本身的“更强自主性”。 第二优先级是一组把“环境条件显式化”的论文。arXiv:2609.05232v1 直接证明，若代码代理不知道 RAM 和时间合同，就容易生成不适配部署约束的实现；一旦把执行基底作为一等输入，模型会明显转向分块、float32、上三角遍历、内存映射等资源感知策略。arXiv:2609.05374v1 则从环境基础设施侧推进，把真实桌面软件封装为可复现的 GUI+CLI 混合环境，缓解纯 GUI computer-use agent 轨迹冗长、效率低的问题。这两篇合起来说明，下一阶段 agent 研究不应只比“会不会做”，而要比“在什么资源合同、接口表面和共享状态下做得更可靠”。 第三条主线是“科学发现/实验自动化正在从 demo 走向可评测、可持续运行的系统工程”。arXiv:2609.04564v1 的自驱实验室框架把 LLM 的解释与诊断职责，和底层贝叶斯优化闭环解耦，强调持久优化状态、异常时再触发 agent 介入；这比“每轮都让 LLM 重新决定一切”的方案更接近真实实验室运行。与之互补，arXiv:2609.05079v1 提出 TruthInsightBench，不再把科学发现代理评成“能否找回隐藏答案”，而是让代理基于冻结数据自行提出可辩护主张，再用固定 judge 对证据成熟度打分。若把这两篇与综述一起看，可以看到一个重要转向：科学 agent 的关键瓶颈已不只是生成分析文本，而是持久状态管理、异常恢复、开放式证据评审和可重复评测。 第四条主线是“领域化训练信号正在替代昂贵在线反馈”。arXiv:2609.04735v1 在小分子设计中用 synthetic task scaling 和课程式后训练，试图绕开昂贵化学 oracle，核心问题是便宜、可验证的合成任务能否迁移到真实 lead optimization。这个思路与很多 agent 工作形成呼应：先找到可规模化、反馈清晰、成本可控的代理任务，再把学到的策略迁移到高价值场景。类似的工程化降本逻辑也出现在 arXiv:2609.05363v1：把 LLM 对电商 trade-up 的推理蒸馏到轻量模型，再用商品类型级 test-time training 做局部适配，从“依赖在线大模型推理”转向“离线蒸馏+在线轻量调整”。 第五条主线是“知识外置与可追溯性”正在重新成为应用系统的核心设计。arXiv:2609.05039v1 的 Qlippy 并不追求让通用大模型端到端包打天下，而是把量子工作流知识放到受控语料和 RAG 管线里，服务于 MLflow/QProv 风格的实验跟踪与复现。它与科学发现、自驱实验室方向有天然连接：一旦系统需要面向真实科研流程，‘答案对不对’之外，‘依据从哪里来、实验如何追踪、修改如何留痕’会变得同等重要。 相对而言，arXiv:2609.05104v1 的 Bellman-grounded cognitive map 更偏经典智能体表示学习问题，价值在于说明环境结构知识如何被紧凑编码并服务成本感知导航；arXiv:2609.05037v1 的道德能动性研究则更偏人机交互与 AI 伦理，对理解 LLM 在社会场景中的“代理归因”很有启发，但和今天最强的系统工程主线相比，优先级略低。 如果按阅读顺序建议：先读 2609.04894v1 建立总框架；再读 2609.05232v1 和 2609.05374v1，看环境约束与交互表面的具体落地；接着读 2609.04564v1 和 2609.05079v1，把视角转到科学 agent 的持续执行与开放评测；然后根据兴趣分流到 2609.04735v1（分子设计）、2609.05039v1（科研工作流 RAG）、2609.05363v1（蒸馏与 TTT）；最后再补 2609.05104v1 和 2609.05037v1。总体判断是：今天最值得关注的，不是“更像人”的 agent 叙事，而是“环境可见、状态持久、评测可信、责任边界清楚”的 agent 系统观。

原始摘要

Computer-use agents have advanced on benchmarks like OSWorld and AndroidWorld, but still act mostly through the GUI, often producing inefficient trajectories. Real-world computer work is hybrid, combining visual-state inspection with precise, high-throughput command-line operations, so capable agents must coordinate both modalities over shared application state. Yet scalable hybrid environments remain scarce because supporting both GUI and CLI over real applications typically requires substantial manual engineering for each application. Existing agents also struggle to use the two interfaces complementarily: CLI-native agents lack visual perception for tasks involving interface state or layout, while GUI-native agents are inefficient for operations better executed through commands. We introduce CUA-Universe, a scalable environment-to-data pipeline that turns real desktop software into hybrid GUI+CLI environments. App-Forge adapts applications into reproducible VMs and command-line surfaces it discovers, wraps, or generates, scaling to 16 applications; Task-Weave synthesizes diverse hybrid tasks of controllable difficulty from reusable operations over seed files; and Path-Steer steers rollouts along efficient hybrid paths and harvests verified trajectories for post-training. Training on this data shifts behavior from inefficient GUI interaction and brittle CLI scripting toward effective GUI+CLI orchestration. Our 9B model improves both success and efficiency on CUA-Verse (Score +39.3 pts; -37% steps, -60% tokens), OSWorld (SR +16.8 pts; -57% steps, -44% tokens), and OSWorld-MCP (Score +7.84 pts; -27% steps, -30% tokens). CUA-Universe provides a scalable path toward more capable and efficient computer-use agents.
