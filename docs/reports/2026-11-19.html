可做研究点

做一个面向多智能体 benchmark 的“链路稳定性审计”复现实验，以 MANGO Arena 类设置比较同模型在不同 API 条件、重试策略和超时处理下的结果漂移。

这直接回应摘要中提出但常被忽略的问题：同种子下，调用链路本身可能改变实验结论。如果这一点成立，很多 agent benchmark 的可复现性需要重新解释。

第一步：先不复现完整论文，先搭一个最小四代理回合制环境，固定 prompt 和需求种子，只改变 API 提供商、重试次数、温度锁定方式或超时回退策略，记录牛鞭效应类指标和违规尝试次数的方差。

风险：真实漂移可能来自模型版本隐式更新而非链路条件；若拿不到原环境，实现差异也会混入结果。

整理并实现一个“环境完整性三分法”小型综述+复现实验框架，把 reward coverage、data coverage、feature coverage 迁移到你熟悉的 agent 任务上。

GUI agent 论文给出了一个很可迁移的环境设计语言，不只适用于 GUI。把这三维框架迁移到网页代理、工具使用或代码代理，可能迅速产出有解释力的对照结果。

第一步：选一个现成任务集，先人工标注每个任务的奖励路径、必要背景数据和可裁剪功能，构造每维度一个最小删减版本，比较训练后在完整环境中的成功率变化。

风险：不同任务中三种 coverage 的边界不清，容易把多个因素混在一起；训练成本也可能较高。

为多步 agent 管线加入显式不确定性传递，对比“点估计中间结论”与“带置信度/证据标签的中间结论”对最终决策的影响。

LProp 指向一个基础但普遍的问题：中间判断一旦被文本化，下游常把它当事实。即便不完全复现论文，也可以先验证这一现象在自己的系统中是否存在。

第一步：在一个多步检索或规划任务上，设计两种中间状态格式：一种只给结论，另一种同时给证据来源和不确定性标签；比较下游步骤的错误传播率和最终成功率。

风险：不确定性标签可能只是增加 token 而非真正改善推理；效果也可能高度依赖 prompt 设计。

复现 ARISE 式“失败驱动外部记忆”最小系统，并专门测试错误规则污染与门控收益。

很多团队都想让 agent 从失败中学习，但真正难点不是写入记忆，而是避免把偶然错误固化。ARISE 的 held-out gate 思路很适合做独立验证。

第一步：在一个小型企业流程或工具调用任务集上，收集失败案例，生成 micro memory，再用一个留出集比较‘直接写入’与‘验证后写入’两种策略的长期表现差异。

风险：如果任务规模太小，门控收益不明显；若 teacher 模型太强，结果可能主要反映额外模型能力而非记忆机制。

做一篇“agent 评测从能力到治理”的短综述，聚焦规则遵守、串谋通信、记忆污染、不确定性传播和基础设施稳定性五个维度。

1. MANGO Arena: Same Seeds, Different Chains Evaluating LLM Agents in a Disrupted Supply Chain

⭐ 👍 👎

一句话

这篇论文提出了一个名为 MANGO Arena 的开源测试环境，用于让四个大语言模型代理分别扮演串行供应链中的四家公司，在正常与“供应商失火”扰动条件下评估其供应链决策行为。摘要显示，该环境同时测量经济结果（牛鞭效应）、规则遵守情况以及串谋提议，且在一个包含3个小型推理模型、2种脚本基线、2种情境和3个需求种子的试验中，LLM 代理普遍显著放大了上游需求波动。

贡献

核心贡献在于把供应链博弈/运营管理中的经典 MANGO 课堂游戏改造成一个面向 LLM 多智能体的统一评测场：同一环境内显式施加硬约束（卡车上限、无赊账现金约束、产能限制）、记录违规尝试、开放但禁止金钱侧支付的公共留言板，从而把运营绩效、规则遵守和潜在串谋三个维度放到同一实验框架中。另一个重要贡献是方法论层面的提醒：摘要指出 API 故障会显著影响评测，因此“同种子、不同链路/调用条件”本身就是需要控制的评测变量。
