可做研究点

做一个“经验蒸馏是否真能跨任务迁移”的小型复现，对比 SPEE 类流程与仅靠反思重写/拒答过滤的基线。

SPEE最关键但也最容易被高估的点，不是单轮性能提升，而是从多轮交互中得到的经验能否在新题、新分布上稳定迁移并被参数化保留。这个问题如果不做任务外验证，很容易把记忆或数据泄漏误判成能力提升。

第一步：选一个公开可复现实验域，如数学推理小数据集；构建三组设置：仅测试时反思、反思+经验文本注入、反思+经验蒸馏后再做小规模策略优化；统一比较原任务与相邻新任务上的提升与遗忘。

风险：原论文摘要未给出完整训练细节与评测协议，复现时可能只能得到概念性而非严格对齐的结果；同时提升也可能来自额外采样预算而非经验蒸馏本身。

基于 GABench 的任务定义，整理一个“图分析 agent 失败模式 taxonomy”，重点拆解工具调用失败、状态丢失、规划错误和图语义误解。

图分析agent当前最大的瓶颈未必是基准数量不够，而是缺少细粒度失败归因。若能把错误拆开，后续才能判断该加更强模型、改工具接口、加中间状态检查，还是改提示结构。

第一步：先不必跑全基准，挑四类任务各抽样少量实例，手工或半自动记录agent轨迹，标注失败发生在检索、工具参数、执行顺序、结果解释哪个环节，并形成统一标签集。

风险：如果没有完整环境与工具代码，早期分析可能受限于论文公开程度；此外不同模型的错误可能高度交织，taxonomy过粗会失去指导意义，过细又难以稳定复用。

把 KC-Agent 与 LEAP 抽象成统一的‘高代价反馈下的代理改进框架’，做一篇短综述或实验设计笔记，比较记忆复用、样本裁剪、原子化更新、回滚验证四个设计维度。

这两篇虽然应用不同，但都在回答同一个系统问题：当一次环境尝试很贵时，怎样减少无效探索并把成功经验变成以后更便宜的决策。把它们放在一起看，可能比单独读任一篇更容易形成可迁移的方法学。

第一步：建立一个2×2或多维对照表，记录每篇论文中的反馈成本来源、保留哪些历史信息、何时终止分支、是否支持回滚、评测指标是什么，再据此提出一个统一框架草图。

风险：由于两篇论文的问题域差异大，强行统一可能流于抽象；如果没有正文细节，某些维度只能基于摘要推测，综述结论需要明确标注证据强弱。

围绕 LEAP 提出的 Difficulty-Conditioned Pruning，做一个最小消融：区分‘节省计算但不掉性能’与‘只是少跑了简单样本导致指标虚高’。

任何自适应裁剪方法都可能带来评测偏差：如果被裁掉的样本本来就容易，平均指标可能并不能说明训练真正更有效。需要检验它到底是在优化学习信号分配，还是在改变样本分布。
