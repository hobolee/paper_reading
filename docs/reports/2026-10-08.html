1. Training Advisors for LLM Agents from Task Outcomes

⭐ 👍 👎
Sergei Polezhaev、Barys Liskavets、Ori Press、Alexander Golubev · PDF
large language model 1 llm 1 language model 1 agent 1 agents 1 ai 1 environment 1
一句话

这篇论文提出了 Caddie，一种面向大语言模型智能体的“顾问/评论者”训练方法：在多步任务执行过程中生成自然语言分析与建议，并仅根据智能体在接受建议后的最终任务成败来训练该评论者。摘要显示其主要验证场景是多跳问答，并进一步测试到交互式基准 MuSiQue、τ^3 和 DeepDive，强调跨基础模型与跨任务迁移能力。

贡献

核心贡献在于把对智能体过程的自然语言反馈训练，从依赖步骤级标注或参考 critique，转为只依赖最终任务结果的强化学习优化；同时保持基础 agent 模型冻结，仅训练 critic/advisor。若摘要表述成立，其重要价值是：一个在单一基础模型上训练出的 Qwen3-4B critic，能够提升多个不同规模、不同架构基础模型的成功率，且在部分未参与训练的模型与域外交互任务上也有效。

1问题

论文想解决的具体问题是：在 LLM agent 执行多步任务时，如何训练一个能够实时给出自然语言分析与建议的外部 critic/advisor，使其真正提高最终任务成功率；并且这种训练不依赖步骤级正确性标签、人工参考 critique 或针对每个基础模型单独定制。更细一点说，它在问：仅凭最终 outcome，能否学出对中间决策有帮助的语言反馈，并让这种反馈跨 agent、跨任务泛化？

2方法

从摘要推测，方法主体是 Caddie：固定一个基础 agent 模型，让其在多步环境中完成任务；另设一个 critic，根据 agent 当前轨迹与环境观察生成自然语言 advice。训练时，以 agent 接收 advice 后的最终成功/失败作为奖励信号，对 critic 做强化学习优化。主训练数据应来自多跳问答，尤其是 MuSiQue 这类需要多步证据整合的 benchmark。评测上，作者似乎在四个不同基础模型上测试同一个训练好的 Qwen3-4B critic，并扩展到 τ^3、DeepDive 等交互式任务，观察成功率变化与跨域迁移。

3价值

最值得关注的亮点有四个。第一，监督信号弱但实用：只用最终任务结果训练过程建议，降低了对昂贵步骤标注和高质量教师 critique 的依赖。第二，训练对象清晰：冻结 base model，只训练 critic，有利于把性能增益归因到“建议质量”而非 agent 本体能力变化。第三，泛化主张较强：单一基础模型上训练出的 critic 能提升多个不同架构模型，若成立说明 advice 具有一定模型无关性。第四，结果表述具体：MuSiQue 上对 Qwen3-4B 超过 25 个百分点的提升，以及在 τ^3、DeepDive 上零额外训练迁移，都是值得重点核对的实证卖点。

完整解释

从题名和摘要看，论文聚焦的是 LLM agent 在多步任务中的“过程指导”问题：agent 会交替进行推理、工具调用和环境交互，但中间决策容易偏航，因此作者训练一个独立的 critic/advisor，在执行过程中输出自然语言分析和建议，帮助 agent 修正后续动作。与常见监督式做法不同，这里没有依赖每一步是否正确的细粒度标签，也不需要人工或教师模型提供标准 critique，而是把 critic 的训练信号压缩为“agent 接受该反馈后，最终任务是否成功”。这意味着方法上很可能把 critic 视为策略，通过强化学习优化其文本反馈，使其最大化下游 agent 的终局成功率；同时基础模型 frozen，说明训练重点是学习“如何给建议”，而不是共同微调 agent 本体。 证据线索主要来自摘要中的几个具体点。第一，训练任务是 multi-hop question answering，说明环境至少包含多步检索、证据整合或链式决策，MuSiQue 被点名为主基准。第二，作者强调“with a single base model”训练 critic，却能泛化到四个基础模型，其中三个未用于 critic 训练，说明他们主张 critic 学到的是相对模型无关的过程性建议，而非只适配某个 agent 的表面风格。第三，摘要给出一个较强结果：在 MuSiQue 上让 Qwen3-4B 成功率提升超过 25 个百分点，甚至超过没有 critic 的 Kimi K3；如果这一比较设置公平，这会是很有吸引力的实证信号。第四，方法还迁移到 out-of-domain interactive benchmarks，包括 τ^3 和 DeepDive，且无需额外训练，说明作者希望证明 advisor 具备任务外泛化，而不仅是问答数据集上的过拟合技巧。 对科研读者而言，这篇工作与“基于结果训练过程监督器”“agentic RL”“LLM-as-critic/coach”几个方向直接相关。它特别适合关注以下问题的人：如何在缺少步骤级监督时训练过程反馈模块；如何让自然语言 critique 真正改善 agent 行为而不是只提高表面解释质量；如何把一个外置 advisor 迁移到不同 backbone agent 上。如果你的方向涉及 tool-using agents、test-time guidance、verbal reinforcement 或 process reward modeling，这篇论文值得优先核对。 但基于当前仅有摘要，也有若干关键信息必须谨慎核实。首先，不清楚 critic 的输入具体包含什么：是 agent 的完整轨迹、当前思维、工具观察，还是压缩状态；建议插入频率是每步、关键步还是固定轮次。其次，不清楚强化学习的具体算法与奖励归因方式：是 REINFORCE、PPO、DPO-like outcome optimization，还是基于采样比较的黑盒优化；自然语言建议的高方差训练如何稳定。再次，所谓“成功率提升 25 个百分点”的基线定义、是否使用相同工具预算、token 预算、推理步数、采样次数，都直接影响结论强度。还有，跨模型泛化是否要求统一提示模板、统一动作空间、统一工具接口，也需要看正文实验设置。最后，摘要没有说明 advisor 的成本：额外调用 critic 是否显著增加延迟和 token 开销，实际部署收益需要结合成本评估。
