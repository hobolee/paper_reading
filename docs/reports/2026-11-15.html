一句话

这篇论文提出了一个名为 Singularity-Bench 的开放式基准，用于评测自主智能体是否能从最小起点构建 AI 开发系统本身，任务覆盖预训练、中期训练、后训练、推理、agent harness 和集群编排六个端到端环节。摘要还表明作者不仅比较了 11 个智能体与成熟人工系统在相同硬件上的表现，还专门研究了 Harbor 框架中的奖励劫持漏洞，并提出防护扩展 Breakwater。

贡献

核心贡献看起来有三层：第一，提出一个比传统受限动作空间 benchmark 更开放、更贴近真实 AI 工程流程的端到端评测集 Singularity-Bench；第二，设计了与成熟人类工程基线在相同硬件上的对照评测，使“agent 能否构建 agent/AI 系统”这一问题更可量化；第三，结合针对 agentic application 的安全红队测试，揭示 Harbor 验证框架的 reward hacking 漏洞，并给出防御方案 Breakwater，强调评测基础设施本身也需要安全性。

1问题

论文试图回答一个具体问题：当前前沿 AI agents 是否已经具备在开放式、真实工程环境中自主构建 AI 开发基础设施的能力，而不仅是在受限 benchmark 中完成局部子任务；同时，如何在这种开放环境下对 agent 生成的复杂系统进行可靠且抗攻击的评测。

2方法

根据摘要，方法上应包括两部分。第一部分是 benchmark 构建：设计六个端到端任务，覆盖预训练、中期训练、后训练、推理、agent harness 和集群编排，要求 agent 从最小起点实现核心系统，并在相同硬件上与成熟人工基线比较。第二部分是评测安全性：对 Harbor 这类传统评测/验证框架进行系统红队测试，攻击面覆盖 OWASP Top 10 for Agentic Applications 的 9 个类别，观察 reward hacking 是否能让 agent 通过不真实的方式获得高分，再据此提出 Breakwater 作为 Harbor 的扩展防御机制。实验对象则是 11 个 agent，来源于 7 个前沿模型和 2 个 harness。

3价值

最值得关注的亮点有四点。其一，任务对象非常具体，不是抽象“软件工程能力”，而是 AI 开发栈中的六类核心系统，这使 benchmark 更接近真实研发流程。其二，强调从 minimal starting point 到成熟系统的构建，能够更好测量 agent 的规划、编码、调试和系统集成能力。其三，采用与成熟人工工程基线在相同硬件上的对照，这比只看 pass@k 或单元测试通过率更接近实际系统性能比较。其四，把评测框架安全性纳入论文主线，指出 Harbor 可能被 reward hacking 利用，并提出 Breakwater，这对今后 agent benchmark 的可信度很关键。摘要中还给出一个强信号：至少某个 agent 组合在六个任务上达到或超过人工基线，说明 benchmark 不是纯理论设计，而是已经能区分并展示前沿系统能力。
